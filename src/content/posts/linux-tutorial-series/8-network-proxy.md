## 强调一下

以上只是咱们这次必看的视频，其余视频大家有时间自行观看。

关于加密代理部分，其实就是解决下面这些问题：

1. 怎么做分流？怎么让该使用代理的网站使用代理，本该能正常访问的网站则不需要代理。
2. 怎么做加密保证传输的信息足够安全，不会被GFW侦测到加密数据特征。

关于 P2P 部分，其实就是解决无公网 IP 的情况下怎么做直通组网，但其实还是要一个有公网 IP 的服务去打洞。和 FRP 内网穿透不同，P2P 不会消耗公网 IP 服务的大量转发流量，打洞期间只会产生少量流量。

如果后面暑假回家想给家里折腾公网 IP 出来：

1. 运营商基本默认只给 IPv6 的公网 IP，是否分配 IPv6 取决于地区的网络资源丰富程度。
2. 你路由器或者光猫看到的 IPv4 地址，一定是大内网 IP（村子/小区内属同一大内网，互相不可访，做了隔离）。
3. 如果想试试自己用家里的宽带给的公网 IPv6 建站，则需要你用软路由或者其他网络设备连接光猫，光猫要让运维设置为桥接。光猫默认路由模式里防火墙完全锁死，所以要改桥接，把防火墙的管理权放到软路由上，再由软路由拨号上网并正确配置 IPv6 相关设置，最后放行防火墙。

为什么大家现在很多都在用 Clash，而不是 V2Ray 等等？

Clash 是基于 Mihomo 内核的代理工具，V2Ray 是基于 Xray 内核的代理工具。Mihomo 在设计的时候就在“分流”部分做了很多，所以我们可以制定各种分流规则，甚至是链式代理；Xray 在这些方面则弱一些。它们两者还有一些细微区别，例如支持的协议略有不同（Xray 支持 xhttp 传输协议，Mihomo 不支持），以及内核性能上的差异。

其实还有个 Sing-box 内核，但因为没有给 Windows 做客户端，所以没有像 Clash 那么火。不过很多服务端已经开始用 Sing-box 了，详情接着看剩余视频。

## 练习题

本节没有实践题。

简答题

1. VLESS、SS 这种，算是加密协议还是传输协议？
2. WebSocket、gRPC 这种，算是加密协议还是传输协议？
3. 如果你想在访问 `blog.yahenix.top` 的时候，使用某个固定节点访问或者直接直连，则 Clash Verge 设置里应该怎么设置？怎么验证你的配置生效？

思考题（附分析过程和思路）

1. 其实校园网目前没有在宿舍区域下发 IPv6，教学楼、院楼也需要连软路由配置，可家里面只有 IPv6 地址，此时还能和家里面进行组网吗？尽可能多地给出组网方案（排除内网穿透）。
2. 如果我们同时使用 EasyTier 做 P2P 组网和 Clash 代理，会发现它们之间的代理极易冲突，因为它们各自都会创建一个 TUN 虚拟网卡（开普通代理除外），且在不启用 TUN 虚拟网卡的情况下，EasyTier 的组网我们无法正常使用。请尝试找出一个或者若干种方案，保证两个代理不冲突（要实操）。
3. （可选）GFW 其实是可以看出来 SSR/VLESS 这些加密协议加密后的数据特征的。请用 Wireshark 工具：使用这两个中的其中一个协议传输数据，并从 16 进制原始数据底层解析它们如何加密数据。尝试搜索或者自己找出它们固有的数据特征。（这个题目就是纯网安了，大家做着玩就行。）
